# 画面構成

「なぜそう決めたか」は [decisions.md](./decisions.md) を参照。

---

## 1. ウィンドウ構成

| ウィンドウ | 役割 |
| :--- | :--- |
| **プロジェクトマネージャ** | プロジェクトの作成・管理。起動時の入口 |
| **メインウィンドウ** | 1つにつき1プロジェクト。複数開ける |

**プロジェクトは常に新しいウィンドウで開く。** すでに開いていればそのウィンドウを
前面に出す。「現在のウィンドウで開く」という選択肢は設けない。

日常的なプロジェクトの切り替えは、OS のウィンドウ操作（`Cmd+\`` / `Alt+Tab`）が担う。

**最後のプロジェクトのウィンドウを閉じるとプロジェクトマネージャが開き、プロジェクト
マネージャを閉じて全ウィンドウが無くなるとアプリが終了する**（全 OS、decisions.md G-1-14）。
macOS ではアプリメニューの「プロジェクトマネージャを開く」（Cmd+Shift+O）からも開ける。

## 2. プロジェクトマネージャ

作成・管理の本拠地。**12 種類の操作**がここに集まるため、独立したウィンドウとする。

### 空状態（decisions.md G-3-3、初回起動時）

プロジェクトが1つも無いとき（初回起動、または全プロジェクトを削除した後）は、
一覧の代わりに「最初のプロジェクトを作る」ボタンだけを大きく中央に出す。
一覧行の情報密度（状態アイコン・エージェント名・パスなど）を空の状態にまで
引きずらない。

```
┌────────────────────────────────────────────────────────┐
│  プロジェクト                                            │
├────────────────────────────────────────────────────────┤
│                                                          │
│                                                          │
│              まだプロジェクトがありません                │
│                                                          │
│           ［＋ 最初のプロジェクトを作る］                │
│                                                          │
│                                                          │
└────────────────────────────────────────────────────────┘
```

### 一覧表示（プロジェクトが1つ以上あるとき）

```
┌────────────────────────────────────────────────────────┐
│  プロジェクト                          ［＋ 新規作成］  │
├────────────────────────────────────────────────────────┤
│  ● 社内ツール改修        claude   実行中                │
│    ~/work/tool                                          │
│                                                         │
│  ○ ドキュメント整理      claude   停止中                │
│    ~/work/docs                                          │
│                                                         │
│  ⚠ 旧プロジェクト        claude   サンドボックスがありません
│    ~/work/old                          ［再作成］       │
│                                                         │
│  ⚠ 移動したもの          claude   ディレクトリが見つかりません
│    ~/work/moved                                         │
├────────────────────────────────────────────────────────┤
│  既存のサンドボックスから追加（2 件）                   │
└────────────────────────────────────────────────────────┘
```

- 行をクリック → **新しいウィンドウ**で開く
- 右クリック → 名前変更 / 削除 / 詳細
- 状態は `sbx ls --json` との突き合わせ結果を表示する。**自動同期はしない**

### プロジェクトの詳細

| 項目 | 内容 |
| :--- | :--- |
| 基本情報 | 表示名、ホストのパス、サンドボックス名、エージェント |
| 操作 | 停止 / 削除 / **OS のターミナルで開く** |
| ネットワーク | `sbx policy log` で拒否された通信の宛先（`host:port`・回数・最終時刻）。宛先ごとに［許可］（このサンドボックスだけ、確認あり）／［無視］。許可済みの宛先は出さず、無視した宛先は折りたたんで並べる（decisions.md N-2-8） |
| 診断情報 | `sbx diagnose` の出力、ACP トラフィックログ、エージェントの `stderr`、`sbx ls --json` の該当エントリ。**まとめてクリップボードにコピーできる** |

「ログ表示」は**診断情報**として実装する。`sbx logs` は存在せず、
`sbx ls --json` はコンテナ名も ID も返さないため `docker logs` にも辿れない。
非エンジニアにとって価値があるのは「ログを読むこと」ではなく
**「問題が起きたときに、誰かに見せられる情報を丸ごとコピーできること」**。

## 3. メインウィンドウのレイアウト

```
┌──────────────────────────────────────────────────────────────────────┐
│ ◆  社内ツール改修 ▾                                      ● 実行中    │ Header
├──┬───────────────┬───────────────────────────────────────────────────┤
│💬│ チャット履歴   │  ┌────┬────┬───┐                                 │
│  │               │  │Tab1│Tab2│ + │                                  │
│📁│ ▸ セッション A│  └────┴────┴───┘                                  │
│  │ ▸ セッション B│  ┌──────────────────────────────────────────────┐ │
│  │               │  │ ↻                                            │ │
│  │               │  │                                              │ │
│  │               │  │           トランスクリプト                    │ │
│  │               │  │                                              │ │
│  │               │  └──────────────────────────────────────────────┘ │
│  │               │  ┌──────────────────────────────────────────────┐ │
│  │               │  │ 思考ログ（直近数行）                          │ │
│  │               │  ├──────────────────────────────────────────────┤ │
│  │               │  │ [chip: auth.ts ✕] [chip: README.md ✕]        │ │
│  │               │  ├──────────────────────────────────────────────┤ │
│  │               │  │ プロンプト入力欄                              │ │
│  │               │  ├──────────────────────────────────────────────┤ │
│  │               │  │ 📎 Mode▾ Model▾ Effort▾      1.2k tok  [送信] │ │
│▶_│               │  └──────────────────────────────────────────────┘ │
└──┴───────────────┴───────────────────────────────────────────────────┘
 ↑メニューバー  ↑サイドコンテンツ
```

### Header

- アプリアイコン
- **プロジェクト名 ▾** — クリックでドロップダウン
  - 最近のプロジェクト（数件）
  - ＋ 新しいプロジェクト…
  - すべてのプロジェクト… → プロジェクトマネージャ
- **サンドボックスの状態**（実行中 / 停止中）を常時表示。タブの接続（`sbx exec` が停止中の
  サンドボックスを起動する）に成功したときと、ウィンドウにフォーカスが戻ったときに
  `sbx ls --json` で取り直す

### サイドバー

メニューバー（アイコンのみ）とサイドコンテンツから成る。アイコンを押すと
サイドコンテンツが現れる。**排他ではなく、押した順に左から並ぶ。**
既定サイズがあり可変で、**サイズは記憶される**。

| 位置 | パネル |
| :--- | :--- |
| 上付き | **チャット履歴**（既定）/ **ファイラー** |
| 下付き | **コマンド実行** |

上付きの2つは**すべて「このプロジェクトの中身」**を見るもので揃っている。
プロジェクト一覧は「外」を見るものだったため Header へ移した。
「変更」パネル（累積 diff の表示と復元）は廃止した（decisions.md A-3-8）。

### チャット履歴パネル（decisions.md C-4 / C-5）

セッション一覧はサイドバー常設にしている（decisions.md G-1-2）ため、バックアップ・削除済みの再発見
導線もポップアップの階層メニューではなく、**同じサイドバー内の展開・トグルで
表現する**。

- **過去セッションの一覧は `session/list` とローカル記録の和集合**（decisions.md
  C-1/C-2 補遺）。行ごとに「両方にある／ローカルのみ／エージェントのみ」を
  控えめな印（アイコンの差し替え＋ツールチップ）で示す。`session/list` を
  取得できていない間は「ローカルのみ」の印を付けない。「エージェントのみ」の
  行をクリックすると、中身の無い `HistoryView`（ローカルに記録が無い旨の説明と
  「再開」）を開く。クリックだけでは接続を張らない。
- **開いているタブ**（今アクティブに接続中のセッション）と**過去セッション**
  （ローカルスナップショットの一覧）を分けて並べる（現状の `ChatHistoryPanel`
  の構成のまま）。「チャット」（開いているタブ）には会話（セッションタブ・履歴
  タブ）だけを並べ、開いたファイルのタブは出さない。行の右クリックは「名前を
  変更」と「閉じる」（タブを閉じるだけで記録は消さない。decisions.md G-1-11）。
- **バックアップを持つ行**には行の左に小さな展開キャレット（▸）を付ける。
  開くと行の下にインデントされたサブリストが現れ、新しい順に
  `{日時} {サイズ KB}` を並べる（表示は新しい20件まで。ファイル自体は
  無期限に残り、削除されない — decisions.md C-4）。行をクリックすると
  Read Only タブで開く。
- 行アイコンはバックアップの有無で軽く変える（バックアップ無しは通常表示、
  ありは少し強調）。
- 履歴リストの末尾に**「削除済みを表示」トグル**（既定 OFF）を置く。ON に
  すると、リスト下部にグレーアウトした削除済みセクションが現れる。行を
  クリックすると Read Only タブで開く。削除は即座に消さずソフトデリート
  する（decisions.md C-5）ため、この一覧が唯一の完全な再発見手段になる。
- **ローカルセッション検索（decisions.md C-6）の入り口**: 「履歴」見出しの
  右寄せに検索アイコン（🔎）を置く。

  ```
  チャット
  　🐭タイトル1
  　🐭タイトル2
  履歴              🔎
  　🕒タイトル1
  　🕒タイトル2
  ```

  タブバーやツールバーに置かないのは、shovel のタブは `session` / `file`
  （Markdown）/ `history` が混在するため、そこに検索を置くと「今開いている
  ファイルの検索か、トランスクリプト内検索（§5、V-5）か、セッション横断検索
  かが曖昧になる」ため。履歴パネルの見出しに紐づけることで、これがセッション
  検索であることが位置だけで伝わる。
  - **検索範囲**: 見出しは「履歴」の下にあるが、検索対象は**このプロジェクトの
    全ローカルスナップショットファイル**（今開いているタブの `.json` を含む、
    `.backup` / `.deleted` も含む）。アイコンの置き場所と検索範囲は別の話——
    今開いているタブの本体はトランスクリプト内検索（§5）で足りるが、そのタブに
    紐づく `.backup` は現在のタブ表示の下には出てこないため、検索対象から外すと
    発見できなくなる。
  - **表示条件**: 「履歴」見出し自体は `pastHistory.length > 0` のときだけ出す
    現状のままだと、「過去セッションは無いが、今開いているセッションのバック
    アップだけ存在する」場合に検索の入り口ごと消えてしまう。見出し・アイコンの
    表示条件は「プロジェクトに何らかのローカルスナップショット（現在・
    バックアップ・削除済みいずれか）が1件でもあるか」に揃える。
  - **ポップアップの中身**: shovel はエンジニア限定のアプリではないため、**Gemini のセッション検索のような
    平易な結果表示**にする。

    ```
    ┌──────────────────────────────────────────┐
    │ 🔎  [検索キーワード入力]              ✕  │
    └──────────────────────────────────────────┘
    □ 削除済みも含める

    結果
    社内ツール改修の相談
    このバグは sbx exec の stdout/stderr 分離が原因で...        9月15日
    テスト設計の下書き                              バックアップ・9月10日
    sbx の path 解決を直したのはこのセッションで...
    ```

    - 結果行はタイトル（太字）＋マッチ箇所を含む一文を `SnapshotEntry.markdown`
      から Markdown 記法を落とした**プレーンテキストで抜粋**（マッチ語だけ
      太字）＋右寄せの日付（月日、年内は年を省略）。**プレビュー欄は置かない**
      ——結果行自体がスニペットを兼ねる。
    - バックアップ／削除済みの行は、日付表示を「バックアップ・{日付}」
      「削除済み・{日付}」に置き換える（アイコンではなくテキストで区別）。
    - マッチングは生 JSON ではなく抽出した平文に対して行う。約200msデバウンス、
      新しいクエリが来たら前の検索をキャンセル。
    - 「削除済みも含める」チェックボックスは検索欄の直下。
    - 結果を開いたときの遷移：`.json`（現行セッション）はアクティブなタブで
      開き直し、`.backup` / `.deleted` は Read Only タブで開く。
- **Read Only タブ**: 既存の `HistoryView`（過去セッションを読み取り専用で
  表示するビュー）を流用する。通常の過去セッション（`acpSessionId` があれば
  「再開」ボタンを出す）とは別に、バックアップ／削除済みを開いたときは
  `readOnlyKind: 'backup' | 'deleted'` を渡し、「再開」「新規開始」の両方を
  隠して、上部の控えめなバーの文言を `Backup · {日時}` / `Deleted · {日時}`
  に切り替える。バックアップ・削除済みの内容を今のライブセッションへ
  書き戻す操作は提供しない。
- タブの種別（`TabInfo.kind`）は既存の `'history'` をそのまま使う（タブバー側
  にアイコンの追加は不要、区別は `HistoryView` 内の表示だけで行う）。ただし
  バックアップ／削除済みタブの識別子は本セッションの `sessionId` と衝突する
  ため、`{sessionId}::backup::{epochMillis}` のような合成 id を使う。同じ
  ファイルを複数タブで開くことも禁止しない（重複オープンのロックは無し）。
  10タブ上限には通常タブと合算する。
- **食い違い検出の通知**: `load` によるバックグラウンド比較（decisions.md C-4）
  で食い違いが見つかり、表示中のタブの内容がエージェント側の最新の記憶に
  置き換わったときは、トランスクリプトに**控えめな notice 行**（ターン終了
  通知などと同じ、目立たない地の文）を1行差し込む。「エージェント側の記録が
  更新されたため、以前の内容をバックアップとして保存しました」といった文言で、
  何が起きたかを利用者が後から気付けるようにする。

### タブ

1タブ = 1セッション = 1 ACP 接続。**最大 10**（切り替えショートカットを
「修飾キー + 0〜9」に割り当てるため）。

| 要素 | 内容 |
| :--- | :--- |
| アイコン | エージェントの絵。状態のバッジもここに載る |
| ラベル | セッション名 |
| 閉じる | **タブを閉じることがセッションのプロセスを終わらせる。** 「切断」操作は無い |
| 右クリック | 閉じる / 他のファイルを閉じる（ファイルのタブだけ）/ すべてのファイルを閉じる。まとめて閉じる操作はチャット・履歴のタブを閉じない（decisions.md G-1-12） |
| ショートカット | 修飾キー（macOS は Cmd、それ以外は Ctrl）+ 1〜9 / 0 で n 番目（0 は 10 番目）、+ ← / → で左右隣（端では反対側の端へ）。←/→ は入力欄・エディタにフォーカスがあるときは効かない（decisions.md G-1-18） |
| `+` | **新しい接続を確立**して新セッション（一番右に開く） |
| ドラッグ | タブを並べ替える。入る位置に縦線を出し、端に寄せると横にスクロール。Esc で取り消し（decisions.md G-1-17） |

タブ内コンテンツ上部の **↻（リフレッシュマーク）** は、**今の接続を再利用**して
`session/new` を送る。接続の確立は高価なので、軽い経路を別に用意する。

タブが表示幅に収まらないときは、**タブの列だけを横スクロール**する（スクロール
バーは出さず、ホイールの縦回転も横へ送る。`+` は常に右端に見える）。前面のタブは
切り替えたときに見える位置まで送る。外側の列ごとスクロールさせると、はみ出した
タブへのフォーカスで画面全体が横にずれるため。

タブのアイコンは、セッション `bot`、履歴タブ・Read Only タブは時計、ファイル
`file`（decisions.md G-1-11）。

開いていたタブ（表示順・チャットに添えたファイルを含む）は、次にウィンドウを開いたときに
並べ直す。セッションのタブは接続せず履歴のタブとして開き、消えたファイル・記録のタブは外す。
並べ終えたら新しいチャットを一番右に開いて前面に出す（decisions.md G-1-17）。

### 分割表示（チャットの右に Markdown を添える。decisions.md G-1-9）

```
┌ タブバー ──────────────────────────────────────────┐
│ 🤖 チャット 1 × │ ＋                                  │
├──────────────────────┬─────────────────────────────┤
│ トランスクリプト       │ [ソース][プレビュー]  spec.md ✕ │
│                      │                             │
│ 入力欄               │ （Markdown エディタ）          │
└──────────────────────┴─────────────────────────────┘
```

- 編集できるファイル（Markdown / Mermaid / HTML / JSON / YAML / テキスト / CSV / TSV）のタブの「チャットの横に表示」、
  またはファイラーの右クリック「チャットの横で開く」で添える。添え先は今のチャットタブ（無ければ直前の
  チャットタブ）。
- 添えた Markdown はそのチャットタブに紐づき、タブバーには独立したタブとして
  出さない。✕ で外す。チャットタブを閉じると一緒に閉じる。
- 境界はドラッグで幅を変えられ、幅は記憶される。
- Cmd/Ctrl+数字でタブを選ぶと、選んだタブだけを表示する（添えていれば分割を
  解除し、Markdown はチャットのすぐ右の独立したタブに戻す）。

---

## 4. 背景タブの通知

| 状態 | 表示 |
| :--- | :--- |
| **権限要求待ち** | アイコンにバッジ。**前面にないタブにだけ**出す（前面のタブは承認カード自体が見えている）。答えるか、自動許可されるか、ターンが終われば消える |
| **ターン実行中** | アイコンの不透明度が約1秒周期で 1.0 ↔ 0.35 に脈動 |
| **ターン終了** | **通知しない。** どのタブもターンを終えるため、通知するとタブ列全体が光り続ける |

## 5. トランスクリプト

React で実装し、`--ra-*` の CSS カスタムプロパティを shadcn のテーマ変数に接続する。

### ブロックの種類

`role` が枠・アイコン・タイトル・地味さを決める。

| role | 見た目 |
| :--- | :--- |
| `USER` | 枠付き。ユーザーアイコン。タイトル無し（アイコンで分かる）。コピー可 |
| `AGENT` | 枠付き。エージェントのアイコンと名前。コピー可（Markdown 原文） |
| `PLAN` | 枠付き。地味。読み取り専用 |
| `THOUGHT` | 折り畳み（`Thinking`）。地味 |
| `SYSTEM` / `COMPLETION` | 枠もタイトルも無い、小さく control された注記 |
| `ERROR` | 同上 ＋ 赤字と警告アイコン |

### ツールコール

- **1行に固定し、折り返さない。** 溢れた分は省略記号で切り、全文は tooltip に置く
  （折り返すとアイコンが独立行に押し出され、静かなログが文字の壁になる）
- 会話ブロックの間にあるツールコールは**1つのグループに畳む**。
  実行中は `Working… 12s`、終了後は `Worked 12s`（履歴の再生では開始時刻が
  無いので `Worked` のみ）
- `kind` によって見せ方を変える

| `kind` | 表示 |
| :--- | :--- |
| `read` / `delete` / `move` | 1行。展開しない。`Read {filename}` / `Delete {filename}` / `Move {old} → {new}`。ファイル名はリンクで、クリックすると（行番号があればその行で）ファイルを開く |
| `fetch` | 1行。`Fetch {host/path}`。URL は外部ブラウザへ。取得内容のみ末尾のキャレットで展開 |
| `search` | `Search {pattern} · {n} results`。ヒット一覧は展開部に |
| `switch_mode` | **例外的に枠付きブロック。** ヘッダは `{Title} → {Mode ID}` を太字で。plan 本文は常時展開 |
| その他 | 標準の折り畳みアンカー |

### 承認カード

- ボタンは `session/request_permission` の `options` から生成する。
  クライアント側で選択肢を発明しない
- **ファイル変更**: ファイル名と行数の増減（`+15 -3`）を1行で表示。
  **チャット内に diff を展開しない。** クリックで Diff ビューを開く。
  承認カードは常にそれを要求したツールコールの行の直下に描かれるため、
  この「クリックで開く」導線はカード自身にではなく、**同じ行にある
  ツールコール側の「差分を表示」リンクが兼ねる**（通常のツールコールと
  同じ diff を指しているため、カードにも複製すると同じ操作が2箇所に
  並ぶだけになる）
- **コマンド実行**: `rawInput` から実行されるコマンドを抽出して表示
- 応答後はボタンを無効化し、選んだ結果をカードに残す

### Diff ビュー

ツールコールの「差分を表示」で開くモーダル（decisions.md N-3-8）。

- **左右（Side by Side、既定）と 1列（Unified）** を見出しのトグルで切り替える。
  既定値は設定の「差分の表示」。トグルはそのモーダルを開いている間だけ効く
- 左右のときはモーダルを広げる。**長い行は折り返す**（横スクロールしない）。
  削除行と追加行は上から1対1で左右に並べ、相手の無い側は淡色の空欄
- どちらの表示でも、対になる行の**変更された単語を濃く塗る**（日本語も単語単位）
- 変更から遠い文脈は `… N 行` に畳む（前後3行は残す）

### 挙動

- **ストリーミング中はプレーンテキスト**で表示し、ブロック確定後に Markdown で
  描画し直す（不完全な Markdown を描画すると表示が暴れる）
- **追記時のスクロール追従は「すでに最下部にいたときだけ」**（閾値 24px）
- **折り畳み時はクリックした行を画面上の位置に保つ**
  （`getBoundingClientRect` の差分で `scrollTop` を補正）
- **送信時はまず最下部へスクロール**してから応答を待つ
- 最下部より下に何かある間は、右下に「最新へ」ボタンを浮かせる
- 終了したターンには「ターンの先頭へ戻る」操作を付ける
- **リンクでウィンドウ内を遷移させない。** `http(s)` / `mailto` は外部で開き、
  プロジェクト内の相対パスはアプリ内で開く。それ以外（`file://`・絶対パス・
  未知のスキーム）はリンクにせず文字として残す（decisions.md の該当項を参照）
- コードブロックのコピーボタンは `pre` の**外側のラッパー**に置く
  （`pre` は横スクロールするため、中に入れるとコードと一緒に流れていく）
- **コピーの確認はボタン自身のアイコン切り替えで行う**（コピー→チェックマークを
  1.2秒）。Transcript は renderer 内で `navigator.clipboard` に直接書き込む
  （architecture.md §5 参照）
- GFM のタスクリストは、エージェントの応答の中でのみ**対話的な選択肢**になる
  （チェックボックス ＋ 右寄せの Send）。Plan / ユーザープロンプト / 思考ログの
  中では読み取り専用。地の文がそのままだと remark-gfm の非活性チェックボックスと
  二重表示になるため、選択肢として抜き出した行は地の文からは取り除く

### トランスクリプト内検索

✅ **解決済み**（[open-issues.md](./open-issues.md) V-5、decisions.md N-1-a）。
Cmd/Ctrl+F でタブ領域の右上に検索バーを出す。Enter で次、Shift+Enter で前、Esc で閉じる。
大文字小文字は区別しない。対象は**タブ領域（アクティブなタブ）の表示されているテキスト**で、
サイドバー・非表示のタブ・折り畳まれた中身・textarea / input・エディタ（CodeMirror）の中身は対象外。
ファイルのタブがソース・分割・「編集」のときは、Cmd/Ctrl+F でエディタの検索パネルを出す。チャットの横の
エディタは、フォーカスがエディタにあるときだけエディタの検索パネルを出す（decisions.md N-3-1「改訂（2026-10-17）」）。
ヒット箇所は CSS Custom Highlight API で塗り、DOM は書き換えない
（`src/renderer/main-window/components/FindBar.tsx`）。検索中に本文が変わったら
（ストリーミング・タブ切り替え）照合し直す。

これは「今見ている1つの会話の中を探す」ものであり、「どの会話だったか分から
ないものをセッションをまたいで探す」ローカルセッション検索（C-6、チャット
履歴パネルの🔎、上記「チャット履歴パネル」節）とは別物。両者を混同しない
よう、入り口の場所を分けている。

## 7. コンテキストチップ

入力欄の上に、送信対象を**チップとして完全に可視化**する。

- **選択範囲の添付は実装しない**

## 8. プロンプト入力欄とアクションバー

### 入力欄

- 既定は 3 行。超えたら内部スクロール（自動拡張はしない）
- 入力欄エリアの上端（トランスクリプトとの境界）を**ドラッグして高さを調整**できる
  - 上へ引くと高くなる。下限は既定の 3 行、上限はウィンドウの高さの半分
  - 高さは**そのタブの中だけ**で保持し、保存しない（タブを閉じると戻る）
  - つまみのダブルクリックで既定の高さに戻す
  - トランスクリプトが最下部にいたら、高さを変えても最下部を保つ
- **Enter = 送信 / Shift+Enter = 改行**（既定）。設定の「送信キー」で
  **Cmd/Ctrl+Enter = 送信 / Enter = 改行** に切り替えられる（decisions.md
  G-1-10。プロンプト入力欄のみ）
- 🔴 **IME 合成中の Enter で誤送信しない。**
  `compositionstart` / `compositionend` と `KeyboardEvent.isComposing` で判定する。
  日本語入力では変換確定の Enter と送信の Enter が衝突する
- 行頭の `/` で**スラッシュコマンド補完**（`available_commands_update` の候補）

### アクションバー（入力欄の下）

```
左から:  📎 添付 | Mode▾ | Model▾ | Effort▾ | （その他の configOptions）
右端:    トークン使用量 | ［送信］
```

- **Mode / Model** は `session/new` が返す `modes` / `models` から構成する。
  エージェントが報告しなければ**表示しない**。選択で `session/set_mode` /
  `session/set_model`（`configOptions` 経由なら `session/set_config_option`）を送る
- **Effort** は `configOptions`（`category = thought_level` / `id = effort`）
  としてのみ存在するため、報告が無ければ隠す
- 知らない `configOptions` も `configId` をキーに**動的に描画する**。
  報告されなくなれば消える
- **トークン使用量は `usage_update` を受け取ったときだけ表示する**
- **送信中は［送信］が［停止］に変わる**（別ボタンを置かない）

## 9. ファイラー

`react-arborist`（仮想スクロールとドラッグ&ドロップを内蔵）。**遅延展開**
（展開したフォルダだけ `readdir`）。

### 既定の表示

| 対象 | 表示 |
| :--- | :--- |
| 通常のファイル | 通常表示 |
| 隠しファイル（`.env` 等） | **通常表示** |
| `.gitignore` 対象（`node_modules` / `dist` 等） | **薄く（グレーで）表示。** 隠さず視覚的に後退させる |
| `.git` ディレクトリ | **常に非表示**（トグルは廃止。decisions.md N-3-5） |

見出しの右に**更新ボタン**（`refresh-cw`）を置き、展開したことのあるフォルダを
読み直す（Finder やターミナルでの変更を、次のターンを待たずに反映するため）。
その左に**ファイル検索**の 🔎 を置く（下の「ファイル検索」）。

`.gitignore` の判定は `ignore`（npm）で行う。`git` コマンドを呼ばないため、
非 git プロジェクトでも、ホストに git が無くても動く。

### 展開できないディレクトリ（decisions.md N-3-9）

ノードを展開しようとして `readdir` が失敗した場合（権限エラー、Windows の
`MAX_PATH`、その他 OS 由来のエラーなど、原因は区別しない）は、エラーダイアログ
やトースト通知は出さず、そのノードの下に**「…」という1行のプレースホルダ**を
淡色で表示するだけに留める。ホバーすると「このフォルダの中身は表示できません」
程度のツールチップが出る。深く調べたくなるディレクトリではない（`node_modules`
の奥や壊れたシンボリックリンクなど）という前提で、通知は不要と判断した。

### 操作

- **ファイルはダブルクリックか Enter で開く。** シングルクリック・矢印キーは選択だけ。
  フォルダはシングルクリックで開閉（decisions.md N-3-4）
- 名前の変更 / 削除 / 移動（ドラッグ&ドロップ可）/ コピー
- 新規ディレクトリの作成 / 新規メモ（Markdown / Text）・新規図（Mermaid）・新規ページ（HTML）・新規設定（JSON / YAML）の作成
- **右クリック**
  - パスをコピー — **プロジェクトルートからの相対パス**
  - コンテキストに追加 — チップとして添付
  - 新規フォルダ / 新規ファイル ▸（新規メモ（Markdown）/ 新規メモ（Text）/ 新規図（Mermaid）/ 新規ページ（HTML）/ 新規設定（JSON）/
    新規設定（YAML））— 右クリックしたノードがディレクトリ
    ならその直下、ファイルならその親に作成する。**空白部分（何もないところ）
    を右クリックしてもメニューが出て、プロジェクトルート直下に作成できる**
  - コピー / 貼り付け — **クリップボード方式**（Alt/Cmd + ドラッグではない）。
    「コピー」で選択ノードを覚えておき、別のノード（またはルートの空白部分）
    を右クリックして「貼り付け」すると、そこへ複製する。貼り付け先に同名の
    ファイル/ディレクトリが既にある場合は「name 2」のように衝突しない名前を
    自動的に採番する（同じフォルダへの「複製」操作もこれで成立する）
  - **アプリ外からの貼り付け** — Finder / エクスプローラーでコピーしたファイル・
    フォルダも「貼り付け」で取り込める（**コピー**。元の場所からは消えない）
  - **Finder で開く / エクスプローラーで開く** — フォルダと空白部分（ルート）の
    右クリックに出す
  - **チャットの横で開く** — 編集できるファイル（Markdown / Mermaid / HTML / JSON / YAML / テキスト / CSV / TSV）の右クリックに出す（§3「分割表示」）
  - 各項目にアイコンを付ける（decisions.md G-1-11）
- **アプリ外からのドラッグ＆ドロップ** — Finder / エクスプローラーからツリーへ
  ドロップすると、そのフォルダ（ファイル行ならその親、空白部分ならルート）へ
  **コピー**する。同名は「name 2」採番。進捗表示は出さない（decisions.md N-3-4）

新規作成したノードは、作成直後に**自動でインライン名前編集（リネーム）状態**
になり、ユーザーが名前を確定する。既定名はディレクトリが `New Folder`
（重複時は `New Folder 2`…）、ファイルが `Untitled.md`（同様に採番）。
名前編集欄はフォーカス時に **拡張子を除いた部分だけを選択状態にする**
（OS のファイラーと同じ慣習。ファイル作成直後にそのままタイプしても
`.md` が失われない）。

ファイル操作は**ホスト側の Node `fs`** で実行する（バインドマウントなので
同じファイル。`sbx exec` を経由するより速い）。削除は `shell.trashItem()`。

### ファイル検索（decisions.md N-3-11）

ファイル名とファイルのコンテンツを、1つの検索語で同時に探す。見た目はローカルセッション検索（§「チャット履歴パネル」）と揃える。

- **入口**: 見出しの 🔎（プロジェクト全体）と、フォルダの右クリック「このフォルダ内を検索」
  （範囲をそのフォルダに替える。ダイアログの「範囲: docs/ ✕」の ✕ で全体に戻す）。
- **ダイアログ**

  ```
  ┌ ファイルを検索 ⓘ ───────────────────────┐
  │ 🔎  [ファイル名・コンテンツのキーワード] ✕  │
  │ 範囲: docs/ ✕                           │
  │ ファイル名                              │
  │ **needle**-notes.md            docs/    │
  │ コンテンツ                              │
  │ **long.md**          docs/ · 121 行目   │
  │ ここに **needle** があります。           │
  └─────────────────────────────────────────┘
  ```

  - ⓘ のツールチップ（decisions.md G-1-15）に検索しないもの（`.` で始まるフォルダ、`node_modules`、フォルダの名前。
    コンテンツはさらにテキスト以外・UTF-8 以外・2MB 超のファイル）を箇条書きで出す。普段は要らない情報なので、画面には常に出さない。
  - 結果は「ファイル名」「コンテンツ」の2つに分け、ファイル名を上に出す。一致の無い方は見出しごと出さない。
    両方とも無ければ「一致するファイルはありません」。
  - ファイル名の行: ファイル名（一致した部分だけ太字）＋右寄せのフォルダ。
  - コンテンツの行: 1ファイル1行（最初の一致だけ）。ファイル名（太字）＋右寄せのフォルダと行番号、2行目に一致を含む行。
  - それぞれ最大100件で、超えたらその区切りの下に「先頭の 100 件だけ」と出す。
  - 約200ms デバウンス、新しいクエリが来たら前の検索は捨てる。検索中は入力欄に回転アイコン。
  - **閉じても検索語・範囲・結果を覚えておく**。開き直すと前回の結果がすぐ出て、裏で検索し直す。
    最後に開いた行には淡い背景の印を付け、見える位置までスクロールする。
- **ファイル名の行を押すと**ダイアログを閉じてファイルを開く。
- **コンテンツの行を押すと**ダイアログを閉じてファイルを開き、一致箇所へ移る。ハイライト表示ではその行を
  中央に寄せて一致箇所を黄色く塗る。エディタのソースでは一致箇所を選択する（Markdown / Mermaid の
  プレビューだけのときは、ソースが見えるモードへ切り替える）。

### ファイルを開いたとき

| 種別 | 開き方 |
| :--- | :--- |
| **バイナリ** | `shell.openPath()` で OS の関連付けアプリへ。判定は**先頭数 KB の NULL バイト**（拡張子では判定しない） |
| **画像** | アプリ内でプレビュー。拡大・縮小・移動ができる（最初は全体を表示）。下端のステータスバーにファイルサイズと幅×高さ（取れない SVG は「—」。decisions.md N-3-2） |
| **テキスト（下記以外）** | **アプリ内で閲覧のみ。** `shiki` でハイライトし行番号を付ける。編集不可 |
| **Markdown / Mermaid / HTML** | エディタ。「分割」「ソース」「プレビュー」を切り替え（既定は分割）。Mermaid のプレビューは図（拡大・縮小・移動ができる。decisions.md N-3-2b「大きい図の表示」）、HTML はスクリプトを動かさずに描いたページ（外部の画像・CSS は読まない。リンクは外部ブラウザで開く。decisions.md N-3-1 再改訂） |
| **JSON / YAML / テキスト（.txt）** | エディタ。「表示」（ハイライト。テキストは色なし）と「編集」を切り替え（既定は表示）。JSON / YAML は設定ファイル用（decisions.md N-3-1 再改訂） |
| **CSV / TSV** | エディタ。「表示」（表。並べ替え・列幅の変更・「1行目を見出しにする」）と「編集」を切り替え（既定は表示）。10MB を超えるものは「既定のアプリで開く」だけ（decisions.md N-3-12） |

エディタの編集欄では Tab / Shift+Tab でインデント（スペース2つ）を増減できる。Markdown 以外は
行番号を付けて折り返さない。JSON は書式の誤りをステータスバーに出し、押すとその位置へ移る。
Shift_JIS のファイルは Shift_JIS のまま保存し、Shift_JIS で表せない文字があれば保存せずにステータスバーへ
その位置を出す（decisions.md N-3-2「Shift_JIS の書き戻し」）。

### ステータスバー（ファイルの表示の下端）

画像・テキスト・エディタ・バイナリ（「既定のアプリで開く」の画面）・大きすぎる CSV / TSV のすべてに出す
（decisions.md N-3-13）。

```
docs/design/ui.md  JSON の書式に誤り（4 行目 1 列目）        9:00:47 に保存しました  32 B  UTF-8  LF
└ パス（押すとコピー）└ 読み取り専用・問題（あれば）      └ 自動保存の時刻・サイズ・文字コード・改行コード
```

- **左端はプロジェクト内のパス**。押すとクリップボードへコピーし、横に「コピーしました」を少しのあいだ出す。
  ツールチップはパス全体。
- 左にはパスに続けて「読み取り専用」と問題（JSON の書式の誤り、書き戻せない文字）を出す。右には自動保存の時刻と、
  サイズ・文字コード・改行コード（画像はサイズと幅×高さ、バイナリはパスだけ、大きすぎる表はサイズだけ）。
- 狭いときは**パスから縮める**。まずフォルダ部分を先頭から省き（`…sign/ui.md`）、それでも足りなければファイル名も
  後ろを省く。右側の項目は縮めない。

ファイルのタブのツールチップも、ファイル名ではなくプロジェクト内のパスにする（同じ名前のファイルを見分けるため）。

## 10. Markdown エディタ

- **分割ビュー**（左=ソース / 右=プレビュー）を基本とし、
  **どちらか一方の単独表示にも切り替えられる**。切り替えボタンにはアイコンを
  付ける（分割 `columns-2` / ソース `square-code` / プレビュー `eye`）
- **チャットの横に添えたとき**（§3「分割表示」）は「分割」を出さず、
  ソースとプレビューの切り替えだけにする
- プレビューは `react-markdown` + `remark-gfm` + `shiki`。
  トランスクリプトとレンダラを共有する
- **autosave。** UI に「保存」ボタンを出さない
- ソースは CodeMirror 6。行番号を付け（Markdown は折り返す）、色は shiki で「表示」・トランスクリプトと同じにする。
  右クリックで OS 標準の編集メニュー（スペルの候補・元に戻す・切り取り・コピー・貼り付けなど。
  decisions.md N-3-1「改訂（2026-10-17）」・G-1-16）
- **キー操作の説明**: ツールバー右端（「チャットの横に表示」の右）の `circle-help`（?）のツールチップに、
  元に戻す・検索・行の移動/複製/削除・矩形選択などのショートカットを OS ごとの表記（macOS は ⌘⌥⇧、それ以外は
  Ctrl+/Alt+/Shift+）で載せる。書き込めないファイル（UTF-8・Shift_JIS 以外）とチャットの横に添えたときは出さない
- **印刷用表示**（ツールバー右の `printer`。チャットの横ではアイコンだけ）: 別ウィンドウで文書全体を
  描き、```mermaid は図として埋め込む。上端に「読み込み直す」「印刷…」。図とハイライトが描き終わるまで
  「印刷…」は押せない。テーマは常にライト。PDF 化は OS の印刷ダイアログに任せる（decisions.md N-3-10）
  - HTML にも同じボタンを出す。印刷用表示はページを画面用に描くだけで、「印刷…」はそのページだけを
    JavaScript を無効にした非表示のウィンドウで印刷する（ページ自身の `@media print` が効く。decisions.md N-3-10）
- 外部で変更されたときの挙動は [flows.md §8](./flows.md) を参照

WYSIWYG 風（インラインプレビュー）は採用しない。

## 11. コマンド実行（下付き）

- 入力欄 ＋ 出力のストリーム表示 ＋ **中断ボタン**
- 履歴は**プロジェクト単位**（decisions.md N-4「履歴の持ち方」）
  - 保存するのは**コマンド文字列のみ**（出力ログ・終了コード・実行時刻などは
    保存しない。出力を見返したい間はドロワー自体が表示し続けている）
  - **同じコマンドを再実行したら重複を残さない**：古いエントリを削除して
    最新の1件として積み直す（MRU 方式。「最近使った順」を保つ）
  - **保持件数は最新20件**（超えた分は古い方から捨てる）
  - **UI は↑キーでの呼び戻しと履歴一覧パネルを併用**（非エンジニアにも
    見つけられるように、シェルの↑キーだけに頼らない）
  - **選んでも即実行しない**：↑キー・一覧クリックのどちらも入力欄へ
    差し込むだけで、実行はユーザーが改めて Enter／実行ボタンを押すまで
    行わない（誤って過去の破壊的なコマンドを実行してしまう事故を防ぐ）
- 実行中も入力欄から stdin へ送れる（`[Y/n]` に答えられる）
- ANSI エスケープは除去。`\r` の進捗行は1行に畳む。出力行数に上限
- 実行前に一言:「入力を求めるコマンドには応答できますが、カーソルで選ぶ画面や
  `vim` などは TTY モードで実行してください」（見出しバーのツールチップに置く）
- **TTY モード（2026-10-08、decisions.md N-4「TTY モード」）**:
  - 入力欄の脇に切り替えを置き、実行ごとにオン・オフできる（既定はオフ。
    状態は保存しない）
  - オンで実行すると、出力の面が xterm.js の端末に替わる。キー入力は端末へ直接
    送られ、`$` / `>` の入力行は隠す。中断ボタンはそのまま押せる
  - ドロワーの高さ・幅が変わったら端末のサイズも合わせる
  - 終了後も最後の画面を残し、終了コードを示す。次の実行かドロワーを閉じるまで
  - 実行中にドロワーを閉じると、その実行は中断する（端末が無くなると操作できないため）
  - `python3` が無いサンドボックスでは、実行時に「このサンドボックスでは
    TTY モードを使えません」と出し、OS のターミナルで開く導線を示す
- 履歴の各行に×を置き、**確認なしで即削除**できる（打ち間違いを残さない）
- 履歴の各行はピン留めできる（最大10件、decisions.md N-4「ピン留め」）。
  ピン留めは一覧の上部に区切り線で分けて固定表示し、20件の押し出しの対象外。
  ピン留めの行には×を出さず、外す操作だけ（外すと通常履歴の先頭に戻る）。
  ↑↓キーでは辿らない
- **チャットと取り違えない見た目にする（2026-10-01）**:
  - 上端に見出しバー（ターミナルのアイコン・「コンソール」・履歴の開閉・閉じる×）。
    上端をドラッグして高さを変えられ、高さは記憶される
  - 履歴の一覧は出力の面との境界をドラッグして幅を変えられる（160〜560px、
    既定 224px）。幅は記憶される。一覧上部の説明文は切り詰めず折り返す
  - 出力と入力は**1つのターミナル風の面**にまとめる。面の色はライト・ダークとも
    周りよりはっきり暗い（`--terminal`）。入力は枠なしで先頭に `$`、実行中は
    同じ位置が stdin 用の `>` に替わる（チャットの入力欄とは別物に見せる）

## 12. テーマと文字サイズ

- ライト / ダーク
- トランスクリプトの**基準文字サイズは設定項目を1つ持ち**、他のサイズは
  そこから導出する（小さい注記は 0.85 倍、コードは等倍）。
  比率を保つべきものは `em`、枠線・角丸・余白は `px`
- ファイルのビューア・Markdown エディタ（ソース/プレビュー）・差分表示は、
  それとは別の**「ファイル表示の文字サイズ」**に従う（差分表示は 0.86 倍）。
  フォントの設定は持たない（decisions.md G-1-13）
- 差分表示の既定のレイアウト（左右 / 1列）も設定で選ぶ（既定は左右、decisions.md N-3-8）
- **テーマや文字サイズの変更では DOM を作り直さない。** CSS カスタム
  プロパティだけを差し替え、スクロール位置と折り畳み状態を保つ
